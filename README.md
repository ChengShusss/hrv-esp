# ESP32-C3 + AD8232 波形采集

当前阶段：ESP32-C3 SuperMini 连续采集 AD8232 的模拟输出，通过板载 USB-C
虚拟串口发送到电脑。Python 桌面程序显示原始与滤波波形，在原始波形上标出
R 峰，并显示、保存 RR 间隔。数字滤波与 R 峰检测目前由上位机执行，
设备保持原始数据采集。上位机支持开始/结束记录，自动计算时域 HRV 和
LF、HF 等频域指标，显示结果并保存报告。频域要求至少 5 分钟连续 RR；
正常心搏间隔（NN）分类尚未实现，结果均标为基于 RR 的估计。

## 仓库内容

- `src/`：ESP32-C3 采样固件及组件构建配置。
- `host/`：串口协议、波形显示、R 峰检测、记录和 HRV 分析程序。
- `test/`：使用合成数据和临时目录运行的 Python 自动化测试。
- `platformio.ini`、`CMakeLists.txt`、`sdkconfig.defaults`：固件构建入口。

构建缓存、Python 缓存、本机编辑器配置、生成的 `sdkconfig.*`（保留
`sdkconfig.defaults` 及其变体）和未使用的 PlatformIO 模板说明均由 `.gitignore` 排除。
`captures/` 中的原始采样、波形图和分析报告保留在本地，不随仓库发布。
下文验证记录中的 `captures/` 链接指向这些本地产物；新克隆无需这些文件即可
编译固件、运行自动化测试和 `--demo` 演示。

## 接线

| AD8232 | SuperMini |
| --- | --- |
| GND | GND |
| 3V3 | 3V3 |
| OUTPUT | GPIO3（ADC1_CH3），当前直接连接 |
| LO− | GPIO6 |
| LO+ | GPIO7 |
| SDN | 3V3，保持工作 |

AD8232 使用 3.3 V 供电。当前没有分压电阻，OUTPUT 直接连接 ADC。
C3 的 ADC 最大衰减档有效量程约 0～2.5 V；留意波形削顶，不将 ADC 码值
直接当成电压。上位机提示近量程边缘点数，但这只是辅助观察，不是完整的信号质量判断。

人体电极连接期间，电脑 USB 或其他有线连接需要适合人体连接的电气隔离。
普通 AD8232 模块本身不提供这种隔离。用普通 USB 线烧录和联调时先取下人体电极。
单独使用电池供电的开发板一旦又接上电脑 USB，仍然存在电脑的电气连接。

## 固件编译与烧录

使用 PlatformIO，平台固定为 `espressif32@6.8.1`，对应 ESP-IDF 5.3.0。
`supermini` 是默认环境，使用通用 ESP32-C3 4 MB 构建定义和 DIO Flash 模式；
实际采样引脚和板载 USB 传输在代码中明确配置。

```powershell
pio run
pio device list
pio run -t upload --upload-port COM5
```

将 `COM5` 换成设备实际串口。此电脑的 PlatformIO 如未加入 PATH，可使用：

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\platformio.exe" run
& "$env:USERPROFILE\.platformio\penv\Scripts\platformio.exe" run -t upload --upload-port COM5
```

用支持数据传输的 USB-C 线连接 SuperMini。首次烧录无法连接时，可按住 BOOT，
按下并松开 RESET，再松开 BOOT，重新查看串口并烧录；烧录后必要时按 RESET。
不要同时打开串口监视器和绘图程序，否则串口可能被占用。

`sdkconfig.defaults` 是配置入口；`sdkconfig.supermini` 由构建生成。
旧的 `sdkconfig.default` 和 `sdkconfig.wifiduino32c3` 不属于当前构建环境。
诊断日志保留在 UART0，ECG 数据通过板载 USB Serial/JTAG 单独发送，
不需要在 GPIO20/21 上另接 USB 转串口模块。

## 数字滤波、R 峰与 RR

算法集中在 `host/ecg_processing.py`，只使用 Python 标准库。
目前先在电脑端保留原始数据、调整参数和核对定位结果；若以后需要脱离电脑独立运行，
再将已验证的处理逻辑和参数移到 ESP32-C3。当前不改变固件或串口协议。

- 显示滤波：二阶 0.5 Hz 高通、50 Hz 陷波（Q=30）、二阶 40 Hz 低通。
  属于因果 IIR 滤波，保留 ADC 码值量纲但去除了直流偏置，波形有相位延迟。
- QRS 候选：额外的 5～20 Hz 带通、约 5 ms 差分、平方和 100 ms 移动平均，
  根据 2 秒预热数据初始化信号/噪声水平，再用自适应阈值寻找候选。
- R 峰回定位：在候选能量峰前 160 ms 至后 30 ms 的原始样本中，
  先做以当前样本为中心的对称 50 Hz 抑制，再做约 9 ms 的对称平滑，
  寻找所选方向的局部峰值；默认向上，避免把较深的 S 波当成 R。
  1000 Hz 下抑制核为 `y[n] = 0.25*x[n-10] + 0.5*x[n] + 0.25*x[n+10]`；
  其他采样率按 50 Hz 重新求系数。它也会改变其他频率的幅度，因此只用于定位。
  所需邻域已缓存在候选确认流程中，时间仍归属中心样本 `n`。
  标记回到原始样本索引，不能将滤波后能量峰或 USB 到达时间当作 R 峰时间。
- 不应期为 250 ms；对 360 ms 内的候选增加斜率检查以减少 T 波误检。
  原始域峰值相对邻域中位数至少 40 ADC 码，作为噪声拒绝条件。
- `RR_ms = (当前 R 采样序号 - 上一个 R 采样序号) × 1000 / 采样率`。
  当前 1000 Hz 下时间步长为 1 ms；确认和显示延迟不加到 RR 上。
- 丢样、设备重启/ADC 分段、电极脱落、量程边缘样本（≤8 或 ≥4087）、
  串口暂停/断连及方向切换均打断分析连续性；恢复后重新预热，第一峰 RR 为空。

`_rr.csv` 的 `r_time_s` 对应 R 峰原始采样时刻，`reported_at_sample` 对应算法确认时刻；
两者不同是正常现象。`analysis_segment` 用于区分一次设备采样段内因质量问题中断的分析段。
R 峰只标在上方原始波形上，下方滤波波形保留其真实的因果延迟。

本实现借鉴 [Pan–Tompkins 原论文](https://www.robots.ox.ac.uk/~gari/teaching/cdt/A3/readings/ECG/Pan%2BTompkins.pdf)
的 QRS 候选检测思路，并非完整复现：未实现漏搏回搜或异位心搏分类，
对显著幅度变化、强运动伪差和复杂形态仍需验证。输出是待核验的 RR 序列，
不能直接视为清理过的 NN 间隔。双二阶滤波系数采用
[W3C Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/) 的标准公式。

### 50 Hz 回定位优化与 HRV 试算（2026-11-17）

现有显示支路已含 50 Hz 陷波；此次为 R 峰回定位支路补充上述对称抑制核，
检测器版本为 `ecg1-r2-centered50`。保留候选检测、质量中断和采样序号计时规则。
原始采样及旧 RR 文件保留，优化后的回放 RR 另存为 `_rr_centered50.csv`。

23 项协议、检测和 HRV 测试通过。已知 R 时间的合成波形包含 300 ADC 码工频干扰、
49.5/50/50.5 Hz 频率、4 种相位、500/1000 Hz 采样率和正反极性；
本组试验中最大 R 定位偏差由 8 ms 降至 1 ms，测试允许上限为 2 ms。
这项合成结果不等于实测心电的定位误差。三份实测记录回放的峰数仍为 20、51、68。
GUI 回放和导出验证通过，原始 CSV 与输入逐字节一致，新 RR 带检测器版本。
已重启上位机启用新版本，COM4 短测收到 11,360 点、11 个 R 峰，丢样和 CRC
错误均为 0，LO 状态正常，画布显示 5 个峰标记；实时窗口保持连接。

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 平均 RR | 857.66 ms | 857.79 ms |

| RMSSD | 16.98 ms | 13.68 ms |
| SDRR（样本标准差） | 22.15 ms | 21.27 ms |

这些是基于 RR 的短记录估计。尚未分类正常/异位搏动，故标准差标为 SDRR，
不能直接声称已获得经过 NN 筛选的 SDNN，也不据此判断健康或压力状态。
记录时长会影响指标，特别是标准差；本次不计算 LF/HF，后续可采集稳定的
5 分钟记录再比较。参考 [超短记录时域 HRV 的原始研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC4586373/)。

## HRV 记录与分析

### 在窗口中记录

1. 连接开发板，确认波形稳定、R 峰标记和 RR 正常，点击“开始记录…”，选择新文件名。
2. 保持姿势和测量条件稳定。若需要 LF/HF，等待“连续有效 RR”达到 300 秒后再结束；
   启动预热、首尾峰确认及信号质量中断会减少可分析时长，通常需录制稍长于 5 分钟。
3. 点击“结束记录并计算 HRV”。结果窗口显示指标、RR 曲线和 LF/HF 功率谱，
   同目录自动保存原始 CSV、RR CSV 和完整 JSON 报告。

丢样、脱落、削顶、暂停或峰方向改变后重新分段，各段独立计算。
例如两段各 3 分钟的 RR 不会拼成 6 分钟来计算频域。结果窗口默认选中最长的
可计算频域的片段；没有符合条件的片段时选最长片段，也可以手动切换。
开始记录前已发生但尚未确认的峰不会补入记录；结束以当时已接受的样本和已确认峰为界，
不补写结束后才确认的峰。

| 指标 | 含义与单位 |
| --- | --- |
| 平均 RR / 平均心率 | RR 均值，ms；心率取 `60000 / 平均 RR`，次/分 |
| RMSSD / ln(RMSSD) | 相邻 RR 差的均方根，ms；及其自然对数，输入单位为 ms |
| SDRR | RR 的样本标准差，ms；未分类 NN，不将其标为已验证的 SDNN |
| pNN50 | 相邻 RR 差的绝对值严格大于 50 ms 的比例，% |
| LF | 0.04～0.15 Hz 频带功率，ms² |
| HF | 0.15～0.40 Hz 频带功率，ms² |
| LF/HF | LF 与 HF 的功率比，无单位 |
| 归一化 LF / HF | 分别为 `100 × LF / (LF + HF)`、`100 × HF / (LF + HF)`，% |
| LF + HF 功率 | 上述两个频带功率之和，ms²；不标为含 VLF 的总功率 |

**LF/HF 来自 RR 随时间的变化，不是对原始心电波形的 50 Hz 干扰做频谱统计。**
本程序在连续 RR 插值支持时长不足 300 秒，或发现待复核 RR 时，不输出频域数值；
界面显示“—”及原因，JSON 对应值为 `null`，不会用 0 代替无效结果。
HF 接近零时 LF/HF 比值也留空，LF + HF 接近零时归一化值留空。

RR 复核规则为间隔超出 250～2000 ms，或偏离局部最多 11 个 RR 的中位数超过 30%。
这是工程复核提示，不是正常/异位搏动诊断；不会自动删点、补点或修正 RR。
时域统计仍保留全部 RR，并显示复核提示。即使无提示，也不能据此确认全部为 NN。
LF/HF 不作为压力评分或交感/副交感平衡结论；本版不计算短记录的 VLF。

### 计算方法与报告

频域版本为 `hrv-r2-welch256s-cubic4hz`。每个 RR 放在其结束 R 峰的采样时刻，
在已有 RR 时间支持范围内做自然三次样条插值至 4 Hz，不外推、不跨缺口。
因此频域支持时长比该段全部 RR 时长少第一个 RR。
随后使用 256 秒窗、周期 Hann 窗和逐窗线性去趋势计算单边 Welch 功率谱密度，
单位为 ms²/Hz；通常以 50% 重叠步进，若末尾尚未覆盖则增加贴齐末尾的完整窗，
实际窗数和尾窗标志写入报告。对精确频带边界插值后用梯形积分得到 LF/HF 功率。
参考 [Kubios 的 HRV 分析方法](https://www.kubios.com/blog/hrv-analysis-methods/) 与
[Welch 功率谱方法说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.welch.html)。
实现使用 Python 标准库，不增加 NumPy/SciPy 运行依赖。

报告保留来源（`serial` / `demo`）、起止时间、实际采样量、丢样与质量统计、结束原因、
原始/RR 文件哈希、检测器和 HRV 版本，以及逐段 RR、时域指标、复核标记和功率谱。
写入失败时停止记录并拒绝用不完整记录计算 HRV；报告保存失败时，已计算的结果仍可
在窗口中查看并“另存报告…”。文件均采用新建方式，不覆盖历史结果。

`host/ecg_recording.py` 负责文件和记录边界，后台任务只读取已经关闭的记录；
`host/hrv.py` 与 `host/hrv_spectrum.py` 计算指标，`host/hrv_view.py` 只负责展示结果。

### 离线重新分析

同一计算逻辑也可通过命令行使用：

```powershell
python host/hrv.py captures/rr_acceptance_20261117_222448_rr_centered50.csv
python host/hrv.py your_rr.csv --output your_hrv.json
```

输出包含每个连续分析段的时域指标、频域指标及可用状态。
每段独立统计，不拼接缺口，不自动剔除或补造搏动；插值仅用于频谱重采样。
不一致的采样序号或 RR 会报错。
不足两个 RR 时，标准差和相邻差指标为空。输出 JSON 使用新文件，不覆盖已有结果。
RMSSD 采用相邻 RR 差平方的均值再开方；SDRR 使用 `N-1` 分母；
pNN50 使用严格大于 50 ms 的相邻差数量 / `(N-1)`。报告同时保留来源、文件哈希、
算法版本、有效时长和分析限制。离线报告不包含只有实时记录时才能获得的采集质量计数。

## 采样与串口协议

ADC1 单通道、12 位、12 dB 衰减，以硬件连续模式 + DMA 请求 1000 Hz 采样，
每块最多 32 个样本。实际采样率受芯片时钟精度影响，HRV 阶段还需要实测验证。
本地 SDK 的 C3 连续采样最低频率为 611 Hz，因此没有直接配置成 250/500 Hz。
采样任务独立于 USB 发送任务；USB 拥塞不会通过串口等待拖慢 ADC 任务。

USB CDC 的 `115200` 是电脑端串口设置，不限制板载 USB 的实际传输速率。
每个数据包是一行 ASCII 文本，前面额外发送一个换行以恢复截断的报文：

```text
ECG1,session,epoch,first_sample,rate_hz,leads_off,count,sample0,...,sampleN,crc32
```

- `session`：每次启动生成的 8 位十六进制标识。
- `epoch`：ADC 缓冲溢出或无效转换后递增，重新建立时间段。
- `first_sample`：本段的首样本序号；即使发送丢块也继续递增。
- `rate_hz`：请求采样率，目前为 1000。
- `leads_off`：bit0 = LO+，bit1 = LO−；每次读出数据块时读取一次 GPIO，
  不表示与每个样本同步，也不保证检测所有电极的接触问题。
- `count`：本包样本数量，1～32；样本为 0～4095 的原始 ADC 码值。
- `crc32`：8 位十六进制 IEEE CRC-32，覆盖 `ECG1` 到最后一个样本，
  不含 CRC 前的逗号和换行，与 Python `zlib.crc32` 一致。

发送队列满或 USB 写入超时时放弃该包，电脑依据采样序号显示缺口；
丢失的首包或末包没有前后数据可对照，不能保证被计数。
ADC 本身溢出后丢失时长未知，固件停止、清空并重启 ADC，增加 `epoch`；
上位机清空时间轴，不把溢出前后的数据拼成连续采样。
缓冲区均有大小限制，启动日志、CRC 错误或残缺包会被忽略，不当成采样值。

CSV 的 `time_s` 是当前 `session/epoch` 内的样本时间，不是墙上时钟。
重新分段、丢样以及电极脱落都必须在后续 HRV 分析时处理。
